# 鼠标拖拽选中

[English Documentation](mouse-selection.md)

全屏模式下，按住鼠标左键在对话区、输入卡片或 Notice 面板上拖动，会高亮选中的文字，并在松开时复制
到系统剪贴板。把拖动持续到对话区上沿或下沿之外，视图会自动滚动，选区随之扩大。

按下/拖动/松开、按字形（grapheme）对齐的列切片、视口锚定与到边缘的自动滚动都来自 pi 的全屏选中。
屏幕本身无法说明的是：哪些区域可以选中，以及这些区域里哪些格子不是正文；本 fork 补的是这两点。

## 可以选中的区域

| 区域 | 拖动会选中什么 |
| --- | --- |
| 对话区 | 消息块正文，去掉 ANSI，每行一段 |
| 输入卡片 | 草稿正文，不含卡片边框与提示行 |
| Notice 面板 | 控制台输出，不含面板边框与 `c/y copy · escape/q close` 提示行 |

在这三块之外的按下不会开始选中，因此标签栏、模型/思考/工作目录徽标、页脚与停靠部件的点击含义保持
不变。

当模态浮层占用指针时（`/settings`、各种选择器、退出确认、扩展对话框），只有 Notice 仍可选中：对话区
与输入卡片根本不会作为可选区域公布。Notice 是非捕获浮层，因此它既不阻塞界面其余部分，自身的文字也
仍可被拖拽复制。

## 输出仍在到达时

在对话区按下鼠标会把它钉住，直到松开。期间流入的输出会画在钉住的行下方，而不是把选区滚走，因此拖动
始终选中开始时的那段文字。松开时，如果按下期间有输出到达、或你自己滚动过，对话区就停在你离开的位置；
什么都没动过则重新跟随。两种情况下，`↓ Jump to latest` 标签、`End` 或滚轮滚回底部都能回到末尾。

## 复制出来的文本

剪贴板只会拿到纯文本，绝不会带上拖拽跨过的边框：

- 语法高亮、块背景与终端序列都会被剥离。
- 输入卡片的边框会一并去掉：只由边框字符组成的行（`────`、`┌─ … ─┐`、`└──┘`）会被丢掉，首尾的
  `│` 列会被去掉，卡片内缩一列会被去掉；在带边框的区域内，同时含箭头字形（`↑↓←→⏎`）与
  `enter|ctrl|shift|tab|scroll|select|accept|cancel` 之一的行按提示行丢掉。
- 写着 `c/y copy` 或 `escape/q close` 的 Notice 提示行不会进剪贴板。
- 宽字符不会被切半：拖动两端落在 CJK 字或 emoji 的哪一半，整个字形都会被完整复制。

如果拖出的范围只含边框行，则不复制也不提示，因此误扫过输入卡片边框不会清空剪贴板。

## 高亮

选中的格子用主题的 `selectedBg` 上色（与对话区搜索命中的同一个 token），不再是反显。背景会在选区内部
每个 SGR 之后重新打开，因此工具块、thinking 块自身的背景色不会把它盖掉。

在带指针悬停提示（cue）的块内 —— 工具调用、摘要卡片、skill 调用、thinking 块 —— 其卡片行上选中的格子会额外加
下划线：悬停提示会把这些格子填成同一个背景色，不加上划线就分不出“悬停”和“选中”。对话区的其余行保持
纯背景，包括块在卡片上方渲染的空白 gap 行。

## 松开之后

松开鼠标左键即复制，并通过 toast 报告 `Copied N chars.`，`N` 是清洗后文本的长度。开启
`fullscreenCopyOnSelect`（默认开启）时，这次松手还会在同一帧里去掉高亮，因此拖动过程中才显示选区；
关闭该设置时，选区留在屏幕上供 `ctrl+x` 复制。剪贴板失败则报告原因；空选区不提示。

`ctrl+x`（`app.message.copy`）仍然复制最后一条助手消息；当 `fullscreenCopyOnSelect` 关闭且屏幕上存在
活动选区时，改为复制该选区，行为与之前一致。
