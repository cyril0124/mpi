# 窗口化对话渲染

[English Documentation](windowed-transcript.md)

默认情况下全屏布局每帧都会渲染全部消息组件，再裁剪到视口，因此帧开销随整段对话增长。本 fork 给全屏
滚动视图换上一个**窗口化**的对话子组件：它只报告虚拟行数，并且只渲染视口附近的行。长对话因此以有界的
单帧开销滚动。

## 工作机制

1. 对话区视口是 `VStack[ScrollView(对话区), 停靠区]`，挂在标签栏之下；它的滚动子组件是
   `WindowedTranscript`（`packages/coding-agent/src/modes/interactive/components/mixcode/windowed-chat/`），
   展开的 widget 面板则用 `HStack` 切分这些行。布局不为 `HStack` 的拉伸子项测量固有高度，因此面板列
   也无法把对话区整体渲染一遍。
2. 布局引擎向它索取行数，以及当前视口需要的行（`packages/tui/src/mixcode/windowed-node.ts` 的
   `WindowedLayoutState`）。
3. 已经滚动过的块保留上次测得的真实高度；从未渲染过的块贡献一个估计值（4 行）。两者之和构成滚动
   范围，因此滚动条与 vim 模式的 `G` / `End` 仍能到达最新输出。
4. 窗口上下各多渲染 20 行（`WINDOW_OVERSCAN_LINES`），滚动一行不会导致相邻块重新渲染。
5. 行号自上而下计数，且只测量窗口内的块，因此追加输出不会移动其上方的行；跳转则渲染它被要求渲染的
   那个偏移。
6. 窗口化子组件还会回报它自己实测后得到的行偏移与总行数，布局按这两个值绘制并滚动。因此某一帧即使只实测
   了部分内容，滚动范围与可见行也保持一致，不会按估算值画出偏移的窗口。
7. 搜索、提问跳转（`ctrl+shift+up/down`）与剪贴板选区会按需索取完整行范围，并整体物化一次；搜索面板
   打开期间会复用已物化的行，直到对话的实测高度变化，因此空闲帧的开销仍与窗口成正比。vim 的用户消息
   跳转通过 `matchingBlocks` 读命中的块与它们的精确行号，因为预览面板要列出每条命中；一次跳转会量测
   整份文档一次。

## 保持不变的部分

- 普通模式不受影响：直接挂载 `documentContainer`，整份文档照常渲染。
- 退出全屏时打印的最终文档仍是完整对话加停靠区。
- 消息组件保留各自缓存（Markdown、Text、Box）。窗口化容器不引入跨帧行缓存：每趟重新渲染窗口，只有一趟
  内的短期缓存，避免同一趟里重复渲染同一个块。
- 鼠标事件仍能命中指针下的块：行以内容坐标传递，容器会先映射回对应块再派发。同一套映射也可以只读地
  查询（`componentPathAtRow`），宿主据此判断某个内容行由什么组成、在该组件的哪一行上；鼠标选中用它区分
  「指针提示卡片内的行」与普通行。
- 估算高度不超过视口窗口的对话会被完整测量，因此短对话报告的是精确高度。

## 限制

- 估计行只有在块进入窗口后才会被实测替换，因此长对话的总高度会随着滚动逐步收敛。行号自上而下计数，
  窗口从最近的一端组装，因此跟随末尾时首帧就会画出最新内容，不受上方块估算误差影响。
- 位于历史中部的单帧开销等于窗口加上到最近一端的距离，与原渲染器“从最新块往回走”的形状一致；在末尾
  与顶部时，帧开销与对话长度无关。
- 窗口化对话区与挂载的 `documentContainer` 不是同一个对象；增删消息的代码继续使用
  `chatContainer`，两棵树都从它读取。
