# 输入坞区

[English Documentation](input-dock.md)

agent 标签页底部的输入框由一个圆角卡片包住，卡片下方的一行取代了 pi 的状态页脚。

## 卡片

```
╭─ ↑ 4 ────────────────────────────────────────── Agent-01 · 12.3k/200k ─╮
│  Describe your next change...  @ files  / commands  ← Home · → widgets │
╰─ ↓ 2 more ─────────────────────────────────────────────────────────────╯
```

- 上边框承载：运行中的工作状态、模式徽标（`[VIM]`、`[SHELL]`、`[ZEN]`，以及编辑器行滚出视野时的
  `↑ N`）、标签页名、以及精确的上下文用量（`12.3k/200k`；数量未知时为 `?/200k`）。工作状态与
  模式徽标只要放得下就会同时显示在同一行。上限后带 `*`（`12.3k/32k*`）表示该窗口由
  `/context-limit` 设置，下方进度条也按它计算百分比。
- 下边框在草稿还有行位于可见窗口下方时显示 `↓ N more`。
- 边框沿用编辑器自身的边框色，因此 vim 模式、shell 模式与 thinking 等级原本的颜色都保留。
- 正文行保留卡片两侧的竖线，文字与左边框之间空出一格；自动补全菜单留在卡片之外，缩进到与正文首列对齐的位置。
- 上下文用量达到卡片所示窗口的 85% 时切换为警告色。
- 输入框为空时，会提示除 `@` 与 `/` 之外作用于它的两个按键：`← Home` 打开 MixCode Home，
  `→ widgets` 切换侧栏。两个提示都取自实际键位绑定；在不会分栏的 TUI 模式下不显示侧栏那一半。

卡片需要十列宽。更窄时改用普通编辑器，以保证工作状态总有位置可放。工作状态会依次降级：
完整消息、转圈图标、被截断的转圈图标；模式徽标先让位于工作状态；在彻底消失之前，工作状态会
先占用标签页名的位置。

## meta 行

```
 󰚩 anthropic/claude-sonnet-4-5     High   ~/proj/pi     [██░░░░░░] 24.1%    main
 ● pi-subagents
```

左侧是模型、thinking 等级与工作目录，右侧是上下文进度条与 git 分支。左侧这三个字段都可点击：指针
悬停会高亮该字段，按下即打开对应的选择器，因此模型选择器、thinking 选择器与工作目录选择器都能用
鼠标进入。见 [工作目录](tabs.zh.md#工作目录)。只有真的画出了工作目录时才有可点击目标：该行由扩展
页脚接管、或宽度不够时，就没有可点的东西。模型写作
`<provider>/<model-id>`，因此在代理或聚合服务上运行时仍能看出真正走的是哪个 provider。进度条
共八格，低于 50% 为绿色，50% 起为强调色，80% 起为红色。该行绘制的字形由 `ui.icons.mode` 决定：
默认 Nerd Font 字形；设为 `ascii`，或 `auto` 判定该终端未知时改用 ASCII。见 [图标](icons.zh.md)。

终端变窄时各部分按固定顺序降级：先去掉分支，再去掉进度条，然后逐段压缩工作目录，模型在截断
之前先退回到只显示 id。右侧整块内容要么完整显示，要么整体去掉，不会把工作目录挤出这一行。

扩展发布状态文本时会出现第二行；vim 模式下该行隐藏。

## 坞区不再显示的内容

pi 的页脚原本占两行：工作目录与会话名，然后是 token 与费用合计加 `percent (auto)`，同一行右侧
是模型名与 thinking 等级；扩展可以再加一行状态。现在标签页名与精确 token 数由卡片上边框承载，
其余由 meta 行承载，但以下三项不再出现在坞区：

- `(auto)` 自动压缩标记，
- 累计的 `↑ ↓ R W` 与缓存命中率，以及费用合计，
- `(sub)` 订阅标记与实验性的 `• xp` 标记。

`/session` 仍会打印 token、缓存与费用部分，`/settings` 仍会报告自动压缩，Home 仍会显示每个
agent 的上下文用量。页脚本来会按条件显示的 `(provider)` 前缀也不再需要：meta 行的模型标签
始终带上 provider。

## Home

Home 没有 meta 行。那里的输入框指向名册选中的 agent，因此卡片显示该 agent 的名字，但不带
自己的上下文用量。
