# 内联组件

[English Documentation](inline-widgets.md)

扩展组件（`ui.setWidget`）默认固定在编辑器上方的坞区里，一个很高的组件会一直占用行数。内联组件模式改为把它们渲染在对话流末尾：组件随对话一起滚动，向上滚动时离开视口，停留在底部时就位于最新内容之后。该模式**默认开启**。

```text
┌─ 坞区模式 (ui.inlineWidgets = false) ──────┐   ┌─ 内联模式（默认） ─────────────────────────┐
│ message 1                                  │   │ message 1                                  │
│ message 2                                  │   │ message 2                                  │
│ ┌ widget: goal ──────────────────────────┐ │   │ ▸ Inline · goal ────────────────────────── │
│ │ 3 tasks remaining                      │ │   │ 3 tasks remaining                          │
│ └────────────────────────────────────────┘ │   │ ▸ Inline · loop ────────────────────────── │
│ [ steered message ]                        │   │ every 5m                                   │
│ > editor                                   │   │ [ steered message ]                        │
└────────────────────────────────────────────┘   │ > editor                                   │
                                                 └────────────────────────────────────────────┘
```

## 开关

| 位置 | 作用范围 |
| --- | --- |
| `mixcode_settings.json` 的 `ui.inlineWidgets` | 新建标签页的全局默认值；在 `/settings` 里改动时也会立即作用于所有已打开的标签页 |
| `/settings` → `Inline widgets`（MixCode 分组） | 等同于直接改文件，无需离开 TUI |
| `/toggle-inline-widgets` | 只切换当前标签页 |

按标签页的模式和下面的折叠状态都**只存在于会话内**：恢复的会话从全局默认值开始，与 vim 模式一致。

`mixcode_settings.json` 位于 `<agentDir>/mixcode-pi/`，即本 fork 与 mixcode-pi 共用的状态目录，两个 agent 读同一份文件：

```json
{
  "ui": {
    "inlineWidgets": true
  }
}
```

文件是允许注释和尾随逗号的 JSON。写入时会保留本 fork 不拥有的键 —— 既包括顶层键，也包括 `ui` 内部的键，因此 mixcode-pi 写在那里的配置不会被抹掉。`ui.inlineWidgets` 不是布尔值时会在启动时给出警告并退回默认值；文件内容损坏时同样只警告。

## 位置

内联块是文档的最后一块：在所有消息之后、待发送队列（Steer / Follow-up）之前，队列本身仍在坞区。全屏模式下它因此会随对话内容一起滚出视口；普通模式下它就是渲染文档的末尾。组件仍可交互 —— 鼠标事件会送到指针所在的那个组件。

aboveEditor 组件排在 belowEditor 组件之前，各自按注册顺序。

## 行预算

一叠很高的组件不能把对话区挤没，所以整块受对话视口推导出的预算限制：

| 视口 | 预算 |
| --- | --- |
| 任意 | `clamp(floor(viewport * 0.7), 6, 24)` |

视口取全屏对话区的高度；普通模式下取终端自身的行数。视口低于 12 行时，6 行下限收缩为视口的一半，把另一半留给对话内容；高于 34 行时 24 行上限先于比例生效。在对话区尚未完成布局时渲染的那一帧没有视口，此时只应用手动折叠状态。

超出预算时，折叠以**整个组件**为单位：

1. 每个 body 要么完整渲染，要么不渲染；绝不截断半个 body。
2. 完整 body 按优先级依次分配：先是你手动展开的组件，其次是最近更新的组件，最后按注册顺序。第一个放不下的组件就是分界点：它以及所有优先级更低的组件都折叠成 `▸ Inline` 标题行。
3. 如果连只有标题行的堆叠都超出预算，整块退化为一行： `▸ Inline · N widgets · /widgets expand`，列宽不足时依次缩短为 `/widgets expand`、`/widgets`。

被预算折叠的标题行会标注 `(auto)`，并保留 `/widgets expand <key>` 提示。列宽不足以放下完整提示时，标题按此顺序依次放弃：`(auto)` 标记、组件 key、`expand` 参数，最短保留 `/widgets`；再窄就不显示提示。标题行裁剪而不换行；两个折叠标题之间不空行，相邻的展开组件之间保留空行。

组件高度变化时有三条规则：

- **对抖动保持，而不是对变化保持。** 当屏幕上是同一批组件（key 与更新次序相同、预算相同、宽度相同）、且完全展开高度变化不超过「2 行」与「预算的 20%」中的较大者时，沿用上一帧的自动决策。尺寸变化、宽度变化、组件更新、组件增删或更大的内容变化都会重新计算，让最近更新的组件拿到 body 行。已展开的块连续两帧都能装进预算后，保持的决策也会被丢弃：内容持续变小时能重新展开，而一行的抖动无法让一个紧接着又溢出的尾部重新展开。
- **手动展开优先。** 用 `/widgets expand <key>` 展开过的组件不会被自动折叠，即使这些固定项本身就超出预算也保留完整 body：宁可让整块溢出，也不违背命令或切断 body。
- **自动决策是可丢弃的。** 它们只存在于会话状态中；`/widgets` 命令会立刻接管对应 key；下一次重新计算会丢弃其余决策。

## `/widgets`

| 命令 | 作用 |
| --- | --- |
| `/widgets` | 在所有组件之间切换折叠/展开。自动折叠的尾部算作已折叠，因此该命令会展开它；再次执行则把手动状态交还给行预算，而不是固定住。 |
| `/widgets expand [key]` | 展开全部组件，或展开指定 key 的组件 |
| `/widgets collapse [key]` | 折叠全部组件，或折叠指定 key 的组件 |
| `/widgets toggle [key]` | 切换全部组件，或切换指定 key 的组件 |

key 精确匹配，可以包含空格。key 不存在或当前标签页没有组件时都会报错。参数补全先给出动作，再给出当前标签页已注册的 key。

## 行为边界

内联模式自身不会抑制该块，编辑器边框也没有内联模式徽标；唯一的例外是[组件侧栏](widget-layout.md)，它在接管组件期间会让对话尾部块让位。组件保留自身渲染的颜色，并会被压缩为每行一条可打印文本：颜色序列保留，其他转义序列与控制字符一律丢弃，因此组件无法移动光标、清屏或把一行拆成两行。组件正文按对话列宽绘制，因此换行位置与较窄的坞区不同。

数组内容组件的 10 行上限在尾部同样生效：注册超过 10 行的组件在到达内联渲染前就已被截断并带上灰色的截断标记，因为这个上限属于注册阶段，与坞区无关。以组件形式注册的组件没有该上限。
