# 组件布局：行预算与侧栏

[English Documentation](widget-layout.md)

扩展组件有两个渲染位置：编辑器上下的固定坞区，以及开启[内联组件模式](inline-widgets.zh.md)后的对话流末尾。两处都限制组件堆叠能占多少行，避免组件把界面其他部分挤出屏幕。每种限制都有自己的标记行，被裁掉时一定会显示出来。

## 坞区预算

编辑器上方与下方的组件**共用一个预算**，因为它们占的是同一块固定坞区：

```text
预算 = 终端行数
     − 标签栏、待发送消息、状态行、footer 占用的行
     − 编辑器自身的最小行数（3 行）
     − 对话区最小行数（6 行）
     − 坞区自己在编辑器上方占的那一行分隔行
```

行数先给 aboveEditor 组件，剩余的按注册顺序给 belowEditor 组件。放不下时：

- 放得下的行照常渲染，并用一行暗色 `… (widgets truncated)` 标出截断；
- 被截断的组件保留已经显示出来的行，不补占位；
- 预算 ≤ 0 时组件一行都不显示；
- 还没有终端尺寸时不限制。

预算**每帧计算**，所以调整终端大小后会自动重新决定，不需要任何组件通知布局。鼠标事件仍然送到指针下的组件，包括只显示了一部分的组件。

## 两种上限

| 上限 | 作用范围 | 标记 |
| --- | --- | --- |
| 本预算 | 坞区里 above + below 的组件堆叠 | `… (widgets truncated)` |
| `setWidget(key, string[])` 内容的 10 行上限 | 单个数组式组件，在进入布局之前 | `... (widget truncated)` |

两者互不替代：单个组件的 10 行上限防的是一行很长的组件，堆叠预算防的是组件数量多、或者以组件形式注册（没有单组件上限）的挂件。以组件形式注册的挂件想渲染多高就多高，只有堆叠预算能限制它。

## 内联模式

当前标签页把组件渲染在对话流末尾时，坞区两个槽位都不渲染，改用尾部自己的预算。规则（优先级顺序、抖动保持等）见[内联组件](inline-widgets.zh.md)。

## 侧栏

空输入时按 `→`（`app.widgets.panel`）打开当前标签页的侧栏：在对话右侧分出一列，收集所有
above/below 编辑器挂件，坞区随之不再渲染它们。输入区仍占满整行，只有对话的行区域被分割。
再按一次 `→` 关闭。开关是逐标签页的会话状态，不落盘；新会话默认关闭。

打开需要至少存在一个挂件，且终端至少 80 列；拒绝时会用 toast 说明原因。已打开后终端缩到
80 列以下时不再分割（避免压扁对话），挂件回到坞区。

侧栏占终端宽度的三分之一（至少 30 列），左侧一条淡色竖线，顶部一行固定的 `Widgets` 标题，
每个挂件前一条 `─ key ─` 分节线，最后一行是 `→ to close` 提示。超宽的挂件行会折行而不是截断；
高于侧栏的内容用滚轮滚动（每次 3 行），隐藏区域用 `↑ more` / `↓ more` 标记；对话上的滚轮仍然
滚动对话。从侧栏开始的拖选只落在侧栏内，点被钳制在正文单元格上，松开时复制选中文本（不含
边框），与其他复制一样报 toast。

扩展交互（选择器、输入框、编辑器或自定义组件）占据输入区时，侧栏保持打开，但滚轮让给对话，
开关键交给获得焦点的组件。[内联模式](inline-widgets.zh.md)下侧栏打开期间尾部挂件块暂停渲染，
关闭后尾部及其折叠状态原样恢复。
